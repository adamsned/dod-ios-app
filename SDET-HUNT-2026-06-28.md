## HIGH

### H1 — Search results race: stale async completions overwrite newer results (no generation guard)
`SearchViewModel.swift:245-304` + `SearchViewModel+T643.swift:111-209`; compounding `SearchViewModel+T637.swift:117-135`, `SearchViewModel+DUT314.swift:27-46`.
The only `Task.isCancelled` check is at :258, **before** `performSearch()` is awaited; nothing inside the fan-out/finalize gates the writes to `items`/`state`/`lastQuery`. Type "chick" (slow REST), then "chicken" (fast/cached) — the fast one lands, then the slow "chick" overwrites it + sets `lastQuery="chick"`, so the next filter re-ranks the wrong base set. Orphaned cook-time/category hydration tasks `reapplyFilters()` on completion against the current set with stale data. (`runImmediateSearch()` bypasses debounce → not test-covered.)
**Fix:** `searchGeneration` token bumped at `performSearch()` start (and when each hydration task spawns); `guard gen == searchGeneration` before every state/cache write + `reapplyFilters()`. Cancelling the Task alone can't stop the body.

### H2 — Cook-journal photo files leak forever; `delete(id:)` has zero callers (2 hunters)
`CookPhotoStore.swift:48-50`, `RecipeStore+CookLog.swift:38-67`, `CookJournalEntryView.swift:208-226`.
`delete(id:)` exists but is never called. Replace photo → old `A.jpg` orphaned; Remove photo → file kept; Delete entry → `deleteCookLog` drops the row, keeps the file. `CookPhotos/` is in Application Support (iCloud-backed, never OS-purged) with no eviction → unbounded growth.
**Fix:** centralize teardown in `RecipeStore`: delete old file in `deleteCookLog` + when `photoID != entry.photoLocalID` in `updateCookLog`/`save()`.

## MEDIUM

### M1 — Rank-up / graduation celebration swallowed by sheet-over-sheet race (my CL-271/272 code)
`FeedView.swift:89-114`, `FeedViewModel.swift:107-126`.
`celebration` is set after two async `cookLogs()` fetches, driving a `.sheet(item:)` on the same FeedView that's mid-dismissing the cookout flow sheet → classic iOS "second sheet swallowed during an in-flight transition." Hero moment silently no-shows on device.
**Fix:** assign `celebration` only after the cookout sheet's dismissal completes (gate on `onDismiss`/dismissing flag), not as fast as the DB reads resolve.

### M2 — Journal photo save swallows disk-write failure (contradicts DUT-312)
`CookJournalEntryView.swift:211-212` vs `FirstCookoutView.swift:319-322`.
`photoID = try? photoStore.save(data)` → on throw, persists `photoLocalID=nil` and dismisses with no error. DUT-312 deliberately surfaces this on the first-cookout path; the journal edit screen (where that snackbar sends the user to retry) silently drops it.
**Fix:** `do/catch` → error snackbar, don't dismiss; on catch keep old `photoLocalID`.

### M3 — ImageLoader coalescing breaks: `defer` clears the in-flight slot unconditionally
`ImageLoader.swift:22-38`.
`defer { inFlight[url] = nil }` clears regardless of whether the slot still holds *this* task → evicts a newer task T2 for the same URL → redundant requests, coalescing contract violated.
**Fix:** `defer { if inFlight[url] == task { inFlight[url] = nil } }`.

### M4 — Settings "Voice:" readout/preview diverges from the voice Cook Mode speaks with
`VoicePreview.swift:86-95` vs `SystemSpeechSynthesizer.swift:96-120`; readout `SettingsViewModel+Voice.swift:21-26`.
`resolvedVoice` lacks the `(language:)`→default fallback that `resolveVoice` has. Locale with only Siri voices → Settings shows "Voice: Unknown" + silent preview while Cook Mode speaks fine via compact fallback.
**Fix:** mirror the two-step fallback; ideally factor shared resolution into DODSupport.

### M5 — Cook Mode "Pause" voice command has no resume path
`VoiceReader.swift:218`, `CookModeViewModel+Voice.swift:142`, `VoiceCommandBus`/`VoiceCommandIntents.swift`.
`pauseVoice()` exists; no `resumeVoice()`, no `.resume` bus case, no `ResumeVoiceIntent`. `VoiceReader.resume()` is dead code. After "Pause," only Next/Previous/Repeat work — all `stop()` + re-read from top, never resume.
**Fix:** add `resumeVoice()` + `.resume` + `ResumeVoiceIntent`.

### M6 — App Intro tour: VoiceOver gets no page-position feedback
`AppIntroTour.swift:72-74, 114-123` (DUT-335).
System indicator suppressed (`.never`) + custom `pageDots` is `.accessibilityHidden(true)` → VoiceOver user has zero "page N of M". First impression for every new VO user.
**Fix:** `.accessibilityElement()` + `.accessibilityValue("Page \(index+1) of \(pages.count)")`.

### M7 — `logCook` has no idempotency: double-tap inserts duplicate entries, inflating rank+streak
`RecipeStore+CookLog.swift:16-29`; sites `CookModeJournalLogSheet.save():211`, `RecipeDetailViewModel.logCook:17`.
Blind `insert` keyed on fresh UUID; the journal-log sheet sets `isSaving` only before the async hop and the detail VM re-enables on error → a retry after a transient error that actually committed lands two rows. Rank/streak derive from `count`.
**Fix:** disable primary button synchronously + dismiss before await; or store-level `guard fetch(id)==nil`.
